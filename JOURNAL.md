# 4/14/2026 2 AM - making an encoder

_Time spent: 4.5h_

Decided to add a USB HID volume encoder to get the project to a Tier 3. The display takes all GPIO pins from the Pi so I decided to use a pro micro usb a board since it has USB HID support also I would not need to code anything on the Pi since it has all the support built in. Picked the Bourns PEC11R-4215F-S0024 for the encoder, it has a metal shaft, 24 detents, push switch built in. Turn for volume, press for play/pause.Designed the enclosure in SOLIDWORKS. very simple design to make just a clean seperate enclosure. 
![Screenshot 2026-04-13 202219](https://stasis.hackclub-assets.com/images/1776133166306-l6vmms.png)
Wrote the Arduino firmware using the HID-Project library. Compiled clean first try after fixing an extra brace. The encoder reads CLK and DT pins for direction and sends MEDIA_VOLUME_UP or MEDIA_VOLUME_DOWN. Button press sends MEDIA_PLAY_PAUSE with 300ms debounce.

# 3/12/2026 3 AM - Building all the backend and frontend plus firmware and planning

_Time spent: 22h_

Spotify discontinued the Car Thing and never replaced it. I had a Pi 3B+ sitting on my shelf, so I decided to build my own; I was going to call it DeskThing, but that name was already taken, so for now, it's PiMusic. Currently, it's running in a virtual environment on my PC. I don't have a proper USB charger for the Pi yet, so deploying actual hardware is the next step. The Spotify part was straightforward until I wanted Canvas, the looping video backgrounds. They aren't available in the public API at all. I researched how the web player loads them and found they use an internal GraphQL endpoint that needs tokens generated by a live browser session. So, I used Playwright to create a headless Chromium instance, captured the network requests to grab the tokens, and used those to fetch Canvas URLs for any track. Videos are proxied through Flask from RAM, so nothing hits the SSD. Anyone can use their own Spotify account; right now, the API app is in development mode, so accounts have to be manually approved first, but once I publish it, that restriction will be removed. The entire frontend uses ES5 to support Chromium on PiOS. The progress bar runs on a 16ms local timer with drift correction, preventing jumps every poll cycle. Apple Music works through Cider's local API on port 10767. I talked directly to the Cider founder—there's no way to get Apple Music Now Playing on a third-party device like Mobile, which was disappointing because I wanted to do that. I built a controller that normalizes Cider's response to match the same format as Spotify, so the frontend doesn't distinguish between them. Apple Music tracks use Spotify Canvas; they do a cross-lookup against Spotify to find the video. The current limitation is that Cider runs on localhost, so only the machine running Cider can use the Apple Music integration. I still need to expose it to the network. I also need to get a charger, deploy to the Pi, design a 3D-printed enclosure, and wire up the touchscreen. (This was done over 3-4 days) (hackatime backs me up on days worked but for some reason time only displays about 2 hours of active coding which is not possible for an app like this)
